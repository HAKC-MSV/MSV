# MSV: Memory Safety Validation


MSV is an LLVM-based **M**emory **S**afety **V**alidation framework, combining [DataGuard](https://www.ndss-symposium.org/ndss-paper/auto-draft-212/) (NDSS 2022) and [Uriah](https://dl.acm.org/doi/pdf/10.1145/3658644.3690310) (CCS 2024).

This repository upgrades the original LLVM 10-based MSV to LLVM 14.0.0, together with the corresponding updates required for SVF, PDG, and the MSV analysis pipeline. The goal is to make the analyses pipeline compatible with HAKC for future development.

The original LLVM 10 version is available at: [Unified Memory Safety Validation](https://github.com/Lightninghkm/Unified-Memory-Safety-Validation).

The analysis integrates:


- [SVF](https://github.com/SVF-tools/SVF) for pointer and value-flow analysis;
- a Program Dependence Graph (PDG);
- the MSV LLVM analysis pass;
- LLVM bitcode generated from Linux kernel source code.


The typical workflow is:


```text
Linux Kernel Source
       |
       | Clang/LLVM 14
       v
  LLVM Bitcode (.bc)
       |
       v
      MSV
       |
       +---- SVF
       |
       +---- PDG
       |
       v
Memory Safety Analysis
```

## 1. Install Dependencies


The current setup is fully tested on Ubuntu 24.04 and 20.04.


Install the required packages:


```bash
sudo apt update
sudo apt install git build-essential python3 ninja-build wget cmake libtinfo-dev libtinfo6
sudo apt install flex bison libssl-dev libelf-dev bc dwarves
sudo apt install gcc-11 g++-11
```


### Ubuntu 20.04


Ubuntu 20.04 may not provide `gcc-11` and `g++-11` through the default configured repositories. If:


```bash
sudo apt install gcc-11 g++-11
```


reports that the packages cannot be located, add the Ubuntu Toolchain PPA first:


```bash
sudo apt install software-properties-common
sudo add-apt-repository ppa:ubuntu-toolchain-r/test
sudo apt update
sudo apt install gcc-11 g++-11
```


There is no need to change the system-wide default GCC. MSV can explicitly use `gcc-11` and `g++-11` while the system continues to use its original compiler.


Verify the installation:


```bash
gcc-11 --version
g++-11 --version
```

## 2. Build MSV


From the root directory of this repository, run:


```bash
bash build.sh
```


The build script performs four major steps as a push-button installation, as shown below.


### 2.1 Build SVF


The script builds SVF with LLVM 14.0.0 support.


SVF provides the pointer-analysis and value-flow-analysis infrastructure used by MSV.


### 2.2 Build LLVM 14.0.0


The script downloads and builds LLVM 14.0.0 from source.


The resulting LLVM toolchain includes tools such as:


```text
clang
opt
llvm-dis
llvm-link
ld.lld
```


The LLVM source tree is also patched with the LLVM modifications required by MSV before compilation.


### 2.3 Build the Program Dependence Graph


The script builds the Program Dependence Graph (PDG) implementation located under:


```text
Unified-Memory-Safety-Validation/program-dependence-graph/
```


The PDG provides program-dependency information consumed by the memory-safety analysis.


### 2.4 Build MSV


Finally, the script builds the MSV LLVM pass and generates:


```text
Unified-Memory-Safety-Validation/build/libUnifiedMemSafe.so
```


This shared library is loaded into LLVM `opt` when running the analysis.


After a successful build, the main components are approximately:


```text
MSV/
├── llvm-project-14.0.0.src/
│   └── build/
│       └── bin/
│           ├── clang
│           ├── opt
│           ├── llvm-dis
│           └── llvm-link
│
└── Unified-Memory-Safety-Validation/
   ├── program-dependence-graph/
   │   ├── SVF/
   │   └── build/
   │
   └── build/
       └── libUnifiedMemSafe.so
```

# 3. Generate Linux Kernel Bitcode


MSV analyzes LLVM bitcode rather than kernel ELF object files.


The repository provides:


```text
build-kernel-bc.sh
```


to generate analysis-friendly LLVM 14 bitcode for an individual Linux kernel source file.


The script:


1. uses the Linux kernel's own Kbuild system to obtain the exact compilation command for the target source file;
2. preserves all kernel include paths, generated headers, architecture options, and Kconfig-dependent definitions;
3. replaces the normal optimization level with `-O0`;
4. enables debug information with `-g`;
5. preserves LLVM value names;
6. disables the `optnone` attribute at `-O0`;
7. generates LLVM bitcode using `-emit-llvm`;
8. also converts the bitcode to human-readable LLVM IR.


The analysis-oriented compilation options include:


```text
-O0
-g
-fno-discard-value-names
-Xclang -disable-O0-optnone
-emit-llvm
```


This keeps the generated IR as close as practical to the original source code and preserves debug metadata for later source-level mapping.


---


## 3.1 Configure the LLVM 14 Path


Before using `build-kernel-bc.sh`, edit``LLVM14`` inside the script and replace it with the LLVM 14 build generated by `build.sh`.


For example:


```bash
LLVM14="/path/to/llvm-project-14.0.0.src/build/bin"
```


---


## 3.2 Prepare the Linux Kernel Source Tree


The script must be run from the **root directory of the Linux kernel source tree**.


For example:


```bash
cd /path/to/linux-source
```


Copy the helper script into the kernel source tree:


```bash
cp /path/to/MSV/build-kernel-bc.sh .
```


Make it executable:


```bash
chmod +x build-kernel-bc.sh
```


The kernel source tree must contain a valid:


```text
.config
```


before generating bitcode.


For example, if a kernel configuration is available elsewhere:


```bash
cp /path/to/kernel-config .config
```


The helper script automatically runs (you do not need to run the following to commands):


```bash
make LLVM=<LLVM14>/ olddefconfig
make LLVM=<LLVM14>/ prepare
```


to update compiler-dependent Kconfig options and generate the headers required to compile kernel code.


---


## 3.3 Example: Generate Bitcode for the MSR Driver


The Linux x86 MSR driver source is:


```text
arch/x86/kernel/msr.c
```


Run:


```bash
./build-kernel-bc.sh arch/x86/kernel/msr.c
```


The script first asks Kbuild to compile:


```text
arch/x86/kernel/msr.o
```


using the actual kernel configuration and build environment.


It then extracts the exact Clang command generated by Kbuild and converts it into an LLVM bitcode compilation command.


After successful execution, two analysis files are generated:


```text
arch/x86/kernel/msr.bc
arch/x86/kernel/msr.ll
```


where:


```text
msr.bc
```


is LLVM 14 bitcode used by MSV, and:


```text
msr.ll
```


is its human-readable LLVM IR representation.


The script also checks that important LLVM debug metadata is present, including:


```text
DICompileUnit
DISubprogram
DILocation
```


---


## 3.4 Generate Bitcode for any Kernel Components


The same workflow can be used for other Linux kernel source files.


For example:


```bash
./build-kernel-bc.sh drivers/char/random.c
```


generates:


```text
drivers/char/random.bc
drivers/char/random.ll
```


In general:


```bash
./build-kernel-bc.sh path/to/source.c
```


produces:


```text
path/to/source.bc
path/to/source.ll
```


Do **not** manually construct a simplified command such as:


```bash
clang -I... driver.c
```


for kernel code.


Linux kernel compilation depends on many architecture-specific and configuration-specific options. `build-kernel-bc.sh` deliberately retrieves the real compilation command from Kbuild so that the generated bitcode uses the same:


```text
include paths
generated headers
architecture definitions
Kconfig definitions
kernel macros
driver-specific definitions
```


as the normal kernel build.


---


## 3.5 HAKC Configuration


The current helper script contains:


```bash
DISABLE_HAKC=1
DISABLE_WERROR=1
```


When enabled, these cause the script to run:


```bash
./scripts/config --disable HAKC
./scripts/config --disable WERROR
```


before generating the target bitcode.


```text
--enable-hakc
```


Later developments of integrating HAKC and MSV do not require these changes, the corresponding values in `build-kernel-bc.sh` can be changed.

# 4. Run MSV


After generating the target `.bc` file, run MSV using LLVM 14's `opt`.


The general command is:


```bash
/path/to/MSV/llvm-project-14.0.0.src/build/bin/opt -enable-new-pm=0 -load /path/to/MSV/Unified-Memory-Safety-Validation/build/libUnifiedMemSafe.so -unified -disable-output -time-passes < /path/to/target.bc
```


For example, for the MSR driver:


```bash
/path/to/MSV/llvm-project-14.0.0.src/build/bin/opt -enable-new-pm=0 -load /path/to/MSV/Unified-Memory-Safety-Validation/build/libUnifiedMemSafe.so -unified -disable-output -time-passes < /path/to/linux-source/arch/x86/kernel/msr.bc
```


### Options


`-enable-new-pm=0`


: MSV is implemented using LLVM's legacy pass manager. LLVM 14 otherwise defaults to the new pass manager.


`-load`


: Dynamically loads the MSV shared library:


```text
libUnifiedMemSafe.so
```


`-unified`


: Invokes the Unified Memory Safety Validation pass.


`-disable-output`


: Runs the analysis without emitting a transformed LLVM module.


`-time-passes`


: Reports LLVM pass execution time.

# 5. Complete Example


Assume the repository is located at:


```text
/path/to/MSV
```


and the Linux kernel source tree is:


```text
/path/to/linux-source
```


### Step 1: Build MSV


```bash
cd /path/to/MSV
bash build.sh
```


### Step 2: Prepare the kernel bitcode script


```bash
cd /path/to/linux-source
cp /path/to/MSV/build-kernel-bc.sh .
chmod +x build-kernel-bc.sh
```


Make sure:


```text
/path/to/linux-source/.config
```


exists.


### Step 3: Generate MSR bitcode


```bash
./build-kernel-bc.sh arch/x86/kernel/msr.c
```


This generates:


```text
arch/x86/kernel/msr.bc
arch/x86/kernel/msr.ll
```


### Step 4: Run MSV


```bash
/path/to/MSV/llvm-project-14.0.0.src/build/bin/opt -enable-new-pm=0 -load /path/to/MSV/Unified-Memory-Safety-Validation/build/libUnifiedMemSafe.so -unified -disable-output -time-passes < arch/x86/kernel/msr.bc
```


The complete workflow is therefore:


```text
bash build.sh
     |
     v
LLVM 14 + SVF + PDG + MSV
     |
     v
Linux Kernel Source + .config
     |
     | build-kernel-bc.sh
     v
    msr.bc
     |
     | LLVM 14 opt
     v
     MSV
     |
     v
Memory Safety Analysis Results
```
